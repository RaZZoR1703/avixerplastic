## Менеджер пакетов Node.js

- Новые Node.js-проекты используют pnpm@11.0.5. Создавай их через new-project --node; для нового проекта не используй npm install/ci, yarn install или bun install.
- В существующем pnpm-проекте соблюдай packageManager и pnpm-lock.yaml. Для воспроизводимой установки используй pnpm install --frozen-lockfile, для команд проекта - pnpm run, для локальных инструментов - pnpm exec.
- Не меняй закрепленную версию менеджера или зависимости без необходимости. Не создавай второй lockfile и не подменяй npm командой pnpm через alias.
- Общий pnpm store оставляй штатным для пользователя и файловой системы. Не создавай отдельный store в каждом проекте; не меняй storeDir работающего проекта массово.
- Переезд npm/yarn/bun-проекта выполняй в отдельной ветке и отдельном checkout без текущего node_modules: импорт lockfile, установка, тесты, сборка, проверка CI/Docker/deploy и готовый откат.
- Работающие node_modules, релизы и сервисы на ходу не менять и не удалять.
- До проверенного переезда старый проект сохраняет свой менеджер и lockfile.
- Инструменты сервера, OpenClaw, Codex и Claude Code не входят в миграцию проектов.
- Не запрещай npm глобально: это может сломать обслуживание сервера.
- В новых Node.js-проектах сохраняй проверку менеджера и один pnpm-lock.yaml.
